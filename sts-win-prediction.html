Slay the Spire win prediction

Predicting, floor by floor, whether a run of a deck-building game will end in a win.

Data
126K human runs, about 3 million floors
Stack
Python, PyTorch, scikit-learn, Jupyter, Google Colab
Links
Source on GitHub
Paper and slides

The question

Slay the Spire is a roguelike deck-builder where a run is a long chain of choices: which cards to take, which relics, which path. Most runs fail, and players rarely know where it went wrong. Could a model look at a run midway, say how likely it is to win, and show where the odds collapsed?

The data

The raw logs record a run's choices, not its state. The first stage is a deterministic replay system that rebuilds the exact deck and relics on every floor, turning 126K human runs into about 3 million floor-level rows. The dataset is too large for GitHub and can demand up to 50GB of RAM, so the notebooks are meant to run in Colab against a shared drive.

Representing a deck

Each deck becomes a high-dimensional vector of card counts. Compressing those vectors with SVD gives compact embeddings, and they capture real archetype structure: decks that play alike end up near each other.

Models and findings

Baselines predict each floor on its own with logistic regression and a small neural network. The sequential models are LSTMs that carry information from floor to floor. They produce smoother and more accurate predictions than the baselines, and win probability becomes reliably separable by about floor 35. Plotted across a run, the predictions form a curve that exposes the choke points where a run stops being likely to win.

The write-up is a full paper, Sequential Win Probability Modeling in Slay The Spire Using Floor Level Representations and Recurrent Neural Architectures, with a lightning talk alongside it.

Where it goes next

The next steps are combining several models for steadier predictions, and building an in-game mod with an evaluation bar inspired by chess.com, so a player can see exactly which big decisions cost them the run.
