Reusable ETL where the work already lived

I built frosts in an environment without a cloud compute platform for ETL. Excel and Power Automate handled ingestion and processing, and I kept writing the same transformations over arrays. I wanted one small library I could reuse instead of rebuilding that logic in every script.

With frosts, one Office Script can read CSV, filter and aggregate the data, then return JSON to the next Power Automate workflow or write the result into a workbook. I wrote the entire TypeScript library and its companion Rust compiler, Permafrost.

The library has been relatively stable for the past couple of years, with occasional compiler adjustments. The open-source repository has received 10 GitHub stars, a small signal of interest beyond my own workflows.

Around 70% less embedded library boilerplate

I estimate that Permafrost removes around 70% of the embedded library code in typical scripts by keeping only the methods they need. The script's own ETL logic stays intact.

A pipeline inside one script

I used a pandas-inspired DataFrame interface to make filtering, grouping, merging, and summaries read as a sequence of transformations. The processing stays inside Office Scripts, without adding a separate compute service.

function main(workbook: ExcelScript.Workbook, csv: string): string { const summary = fr.read_csv(csv) .filter("Amount", value => Number(value) > 0) .groupBy("Category", { "Amount": "sum" }); summary.to_worksheet(workbook.getWorksheet("Summary")); return summary.to_json(); }

The cost of shipping one namespace


Office Scripts did not give me a package-import workflow, so I shipped the library as a namespace copied into each script. That made it easy to use in the existing environment, but every script carried methods it never called. The duplicated library code cluttered the script files stored in SharePoint.


I built Permafrost to keep the convenience of the full library during development and trim the copy that ships with each workflow. It reads the script, identifies the methods it calls, and follows their dependencies through a call graph. That last step matters: a method can depend on helpers the script never calls directly. Permafrost retains those dependencies and the constructor, removes unused methods and internal comments, and copies the result to the clipboard.



Maintaining a small tool


The published Permafrost beta has Windows and macOS builds. The current version uses a small custom parser and a dependency graph to identify the code to keep. I plan to build Permafrost v2 around a TypeScript compiler in Rust; that remains future work.


The repository includes a quickstart, an API reference, and worked examples, including a reservation pipeline that expands stays into nightly rows and aggregates monthly results. Those examples give other users a starting point for adapting the library to their own workflows.
